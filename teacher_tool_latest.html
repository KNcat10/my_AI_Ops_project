AAI 批量测评区
用于批量导出任务、交给外部大模型生成/评分，再把评审 JSON 导入系统生成测试记录。

批量自动化测试中心
适合 30 个模板 × 3 个样例的批量测试：导出任务 → 交给模型批量生成/评分 → 导入评分 JSON。

4. 详细评分细则

每项 0-20 分

建议打分方法：先按“是否满足本次样例 expected”判断，再看输出能否直接交给讲师或运营使用。默认不要轻易给满分；18 分以上必须同时满足结构清楚、贴合输入、可直接落地、表达专业、没有明显跑题或编造。
结构完整性 看模块是否齐全
18-20完全按 Prompt 要求输出，标题、层级、关键模块齐全，顺序清楚。
例：教案包含教学目标、知识点、课堂流程、项目/练习、差异化支持、课堂卡点、作业/展示。
15-17主结构基本完整，但少 1 个重要模块，或层级略乱但仍能阅读使用。
12-14有基本内容，但模块缺失较多，段落堆叠，读者需要自己重新整理。
0-11没有清晰结构，只有泛泛描述、列表残缺、输出截断，或与要求格式明显不一致。
场景匹配度 看是否像真实教培业务
18-20精准使用本次样例变量，体现课程类型、Level、年龄、班级人数、课时和项目制特点。
例：Python L1 写 150 分钟、10 人满班、五六年级、从 Scratch 过渡到文本代码，并安排可运行展示作品。
15-17大体符合少儿编程和教培场景，但对 Level、年龄、班级特点或课时体现不充分。
12-14只是泛泛教育表达，能看出是课堂/运营内容，但不像小码王少儿编程真实工作流。
0-11明显跑偏到成人培训、学校学科课、通用写作，或忽略 Python/Scratch、教培、家长/讲师场景。
可执行性 看能不能直接拿去用
18-20给出具体步骤、时间分配、代码/话术/表格/清单、验收标准，讲师或运营可直接照做。
例：150 分钟教案明确导入10分钟、讲解40分钟、练习60分钟、总结20分钟、拓展20分钟，并给课堂展示任务。
15-17大部分可执行，但部分步骤不够具体，需要讲师补细节。
12-14有方向但缺少步骤、例子或落地材料，需要较多人工二次加工。
0-11只有原则口号，如“加强互动”“注意差异化”，没有可操作动作。
专业性 看术语和表达是否专业
18-20准确使用教育、少儿编程、Python/Scratch、学情分析或运营管理术语，表达符合岗位场景。
例：能区分变量、循环、函数、列表、事件、广播、克隆、调试、迁移、课堂卡点、续费沟通、成长反馈。
15-17专业表达基本正确，但术语深度一般，或缺少少儿编程行业细节。
12-14语言通顺但偏通用，专业术语少，像普通 AI 生成文本。
0-11概念错误、代码知识错误、年龄认知不匹配，或出现明显外行表达。
稳定性 看是否守约束、不乱编
18-20严格遵守输入变量和边界条件，不跑题、不空泛、不编造不存在信息；同一模板不同样例下风格和质量稳定。
例：Scratch 不写成 Python 代码课；Python L1 不突然讲高阶算法；家长沟通不虚构学生真实成绩。
15-17基本稳定，只有少量泛化表达或轻微遗漏，不影响整体使用。
12-14存在明显模板化、重复、轻微跑题、约束遗漏，使用前需要复核。
0-11输出截断、前后矛盾、编造事实、课程类型混乱，或无法确认是否满足样例要求。
